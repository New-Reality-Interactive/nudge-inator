- (direction) Review finding F1: no app code runs when a notification or alarm fires. Every future transition (give-up close, takeover, Not Done expiry, follow-up removal, snooze countdown vs takeover or quiet hours) has to be precomputed at the last run, and statuses read later have to be derived from the clock. Delivered notifications for a closed occurrence can only be removed the next time the app runs.
- (decision) Q1 paradigm: functional core, imperative shell, with desired-state reconciliation. A pure engine (NudgeCore) maps (reminders, config timeline, events, settings, capabilities, now) to derived occurrence states and the full desired delivery plan; a reconciler diffs the plan against UNUserNotificationCenter and AlarmManager and applies the difference. Statuses such as Missed are derived, never written by a timer. The How It Nudges preview calls the same engine. Binds: engine, scheduler, preview, tests. Prevents: preview and scheduler drifting apart; state that depends on code running at fire time. Rejected B (stored state machine with incremental scheduling): no handler runs at the give-up limit or a takeover, so it breaks exactly where F1 bites.

- (decision) Process model: the app process is the only writer. Every App Intent (Siri and App Shortcuts, alarm stop and snooze, Live Activity Done) and every notification action runs in the app process; the widget extension only renders from alarm metadata and never opens the database. No App Group container for the database. Binds: intents, widget, store. Prevents: two processes writing one SQLite file.
- (decision) Mutation path: every state change is a Command sent to one CommandGateway actor, which loads state, asks the engine for the resulting events, writes them in one transaction and then runs the reconciler. Commands are idempotent and name their occurrence; a command against a closed or unknown occurrence writes nothing. Binds: UI, notification delegate, intents, background refresh. Prevents: a Watch Stop and a notification Done racing; double-closing.
- (decision) Identity: an occurrence's key is the reminder ID plus its due date-time as wall-clock time in the reminder's zone mode, so keys are known before any row exists and are stable across time-zone changes. Notification request IDs are derived strings; AlarmKit IDs are UUIDv5 values derived from the same strings. Binds: engine, reconciler, action routing. Prevents: two units naming the same delivery differently; an action that can't be traced to its occurrence.
- (decision) Occurrence materialization: an occurrence is a projection until an evaluation finds it due; then its row is written with its due instant frozen. Status is still derived. Prevents: past occurrences of a follow-the-iPhone reminder moving when the zone changes.
- (decision) Delivery ledger: the reconciler records every delivery it schedules (notification or alarm) with its occurrence, nudge index, urgency, channel and fire time, and marks cancellations. History's "Nudge 2 · Normal · notification" lines are ledger entries whose fire time has passed and that weren't cancelled. The ledger is also the reconciler's expected state. Prevents: history that claims a channel the nudge never used.
- (decision) Edits: reminder configuration is versioned with effective instants, so the engine evaluates each nudge with the configuration in effect at that instant (brief §3 Edit: schedule from the next due time; strength, limit, Ignore Quiet Hours from the next nudge).
- (decision) Alarm limit: unknown, so it is learned. When AlarmKit throws maximumLimitReached, the reconciler records the count that succeeded as alarmCapacity, a capability the engine plans against; overflow nudges become Time Sensitive notifications in the notification budget. Revisited on each reconcile by trying one more.
- (decision) Reconcile triggers: launch and foreground; after every command; BGAppRefreshTask (best effort); significant time change and NSSystemTimeZoneDidChange; notification settings read on foreground; AlarmManager authorizationUpdates and alarmUpdates; quiet-hours and reminder edits.
- (decision) Snooze on an alarm: the snooze intent checks whether the snooze would end after a takeover, inside quiet hours (for a reminder that doesn't ignore them) or on the third snooze; then it cancels the system countdown and schedules a fixed replacement alarm (or nothing), so no alarm rings for a closed occurrence or during quiet hours.
- (decision) Done follow-up: sent by the alarm stop intent, in the app process; removed by the reconciler on its next run after the next occurrence falls due, or at once when Not Done is used. A Not Done action that arrives after the window is a no-op.
- (decision) History retention: events and ledger entries older than 90 days are pruned on reconcile, except that each reminder's latest occurrence and its events are always kept (Not Done and carry-over need them).
- (decision) Export Data: a JSON document, schemaVersion 1, ISO 8601 instants with offsets, IANA zone IDs, tags by name, reminders with their occurrences and events. Not importable. File name nudge-inator-YYYY-MM-DD.json.
- (decision) OS split: Core never checks the OS. All #available checks live in the shell: one Capabilities value (alarmsAvailable, alarmCapacity, timeSensitiveAllowed, notificationsAllowed, assistiveAccessScene) and a small set of view modifiers that wrap iOS 26-only APIs (tabBarMinimizeBehavior, navigationSubtitle, Tab(role: .search)). UIKit only for UITabBarAppearance on iOS 18.
- (decision) Layout: decisions by width and size class, never by device idiom or interface orientation. WWDC26 session 278 says iPhone apps are fully resizable on iOS 27 (iPhone Mirroring always reports portrait), so "landscape" rules mean compact vertical size class.
- (decision) Logging: os.Logger only, with reminder titles, notes and tag names marked private. No analytics or third-party SDKs other than GRDB. Crash reports come from TestFlight and App Store Connect.
