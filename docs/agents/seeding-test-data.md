# Seeding test data

Part of the device testing guide ([device-testing.md](device-testing.md)).

A Debug build loads a named set of reminders, tags and settings when it is launched with `NUDGE_SEED`, and removes them when launched with `NUDGE_SEED=clean` (#134). A launch without the variable does nothing, and Release builds contain no seed code: every seed file is wrapped in `#if DEBUG`, and `scripts/check-release-has-no-seed.sh` checks a Release build in `scripts/test.sh` and the archive in `scripts/archive-and-upload.sh`. The seed is for manual checks; automated tests never trigger it, and the test host has no model for it to act on.

```
scripts/device-seed.sh search          # load the "search" set on the connected iPhone
scripts/device-seed.sh search sent     # the same, with NUDGE_SHARING_STANDIN=sent
scripts/device-seed.sh clean           # remove what was loaded
```

`scripts/device-seed.sh` returns once the app logs that it did it and fails otherwise (a locked phone, an unknown set, no answer), so tell the developer a state is loaded or cleared only after it succeeds. It records each launch for the next phone-check report. For another device, such as the iPad, launch by hand, with the variables in `devicectl`'s `-e`:

```
xcrun devicectl device process launch --terminate-existing --device <id> \
  -e '{"NUDGE_SEED":"search"}' com.newrealityinteractive.nudgeinator
```

- Install the Debug build first (steps 2 and 3). To see the app's log messages on the Mac, add `--console` to the launch and put `"OS_ACTIVITY_DT_MODE":"YES"` in its `-e` dictionary, beside any `NUDGE_SEED`: `--console` alone carries only what the app prints to standard output, and the app logs through `Logger` (found in #216's device check). The seed logs `loaded(...)` or `cleaned` under the `DeviceSeed` category; the sharing adapter logs `Sync engines started`, each account read and each account-change event under `CloudKit`.
- The data goes through the model's own add and delete, so it is stored and scheduled like data made by hand, and it survives a force-quit. Loading a set again replaces its reminders, so one copy is left.
- A seeded reminder keeps the creation date its set gives it: `createdAgo` seconds before the load, so the Created sort has different dates to sort by (#248). The app's add stamps a reminder made by hand with now and ignores the date it carries, so the seed adds through `AppModel.addKeepingCreationDate`, a Debug-only add that skips the stamp. A set that leaves `createdAgo` out gets the load time.
- Removal reads a record the load kept in the app's `UserDefaults`, and acts only on what is in it: the reminders by their fixed IDs, and the tags the seed created. A tag the person already had under a set's tag name is used but never recorded, so removal leaves it, and so it does a tag a reminder of theirs now uses. Their own reminders are never touched, whatever their titles.
- A set can make a span before the load read as quiet hours (#369): quiet hours that were on over it and turned off at the load, saved with the schedules each edit replaced, so the set's nudges due in it count as held. The person's current schedules don't change. The load records when it added the span, and removal takes away that one entry and no other.
- A set can change settings (the Reminders tab's sort, the Default Pace). The first load records each one's earlier value, and removal puts it back. The record holds nothing between the launches but this; **Delete All Data** in Settings does not clear it, so a `clean` after it finds the reminders already gone and only restores the settings.
- A set's reminders have Break Through Focus off and none is Relentless (`urgency-cards` has one, for its Urgent card), so no set schedules an AlarmKit alarm, which uninstalling would leave behind. A test guards that. The exceptions are named in the test (`setsThatRing`): `urgency-cards` and, by the developer's go of 2026-11-22 (#379), the four quiet hours alarm sets below, whose reminders have Break Through Focus on so their Urgent nudges are real alarms; `clean` deletes them, which cancels the alarms and notifications, and every run of one ends with `clean`.
- Removal deletes each reminder through the model's own delete, so it cancels the reminders' pending notifications and alarms through the same plan a delete makes, and removes their delivered notifications from Notification Center (#156). After the `clean` launch, check the phone is as it was: the Reminders tab holds only the person's own, and the sort is the one they had.
- The seed does not undo data the person added to a set's reminders by hand, or changes they made while it was loaded; the `clean` removes the set's reminders whatever state they are in.

Add a set: copy `Packages/NudgeEngine/Sources/NudgeDeviceSeed/SearchSet.swift` to a new file, change its name, tags, settings and reminders (give each reminder a new fixed UUID; due times and creation dates are seconds from the load, a due time rounded down to the whole minute), and add it to `SeedSet.all` in `SeedSet.swift`. The tests check every listed set: unique name and IDs, no alarm (unless the set is named in `setsThatRing`, which the developer approves, #379), tags declared, and a clean load and removal. A set with a quiet window timed from the load sets `quietWindow`, and one that rings sets `breakThroughFocus: true` and, to shorten the waits, `pace: .consistent(wait:)` on its reminders. A new setting needs a case in `SeedSetting` and in `ModelSeedTarget` (`App/DeviceSeed/DeviceSeedLaunch.swift`). The target's tests run with the engine's: `cd Packages/NudgeEngine && xcodebuild test -scheme NudgeEngine -destination 'platform=macOS'`, or `scripts/test.sh`.

Lessons from ticket 29:

- Simulator screenshots missed a failure that only showed on the phone: at the largest text size in landscape the keyboard covered the rename sheet's error. Check landscape plus largest text on the device whenever a sheet has a text field with a message under it.
- A Form section footer sits below its field and goes behind the keyboard; in compact height put such a message in the section header.
- VoiceOver speaks "#" as "number sign".
