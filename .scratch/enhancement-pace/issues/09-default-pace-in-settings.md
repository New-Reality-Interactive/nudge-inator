# 09: Default pace in Settings

**What to build:** Settings gets a Default pace row, Consistent · 10 min out of the box, using the same Pace and Every controls as the form. Every new reminder starts with it, whether made with + or from a tag's list, and keeps its own pace from then on, so changing the default never moves an existing reminder. It survives relaunch, and Delete All Data sets it back. This ticket also writes the beta note that testers run Delete All Data and reinstall. Spec stories 36–42 and 48.

**Blocked by:** 08.

**Status:** resolved

- [x] The Default pace is Consistent · 10 min when nothing is stored, and a chosen one survives relaunch.
- [x] A new reminder draft starts with the Default pace from every place one is made: + on Now, + on My Day, and + on a tag's list.
- [x] Changing the Default pace leaves every existing reminder's pace as it was.
- [x] Delete All Data sets the Default pace back to Consistent · 10 min.
- [x] Settings' Nudges section has the Default pace row with the form's controls, as in the proposed mockup.
- [x] The Default Pace row reads "Consistent · 10 min" and opens a Default Pace page with the form's Pace and Every controls and the note "New reminders start with this pace. Changing it doesn't change the reminders you already have."; the screenshot harness walks to that page.

## Before you start

- Builds on: ticket 07b: the form's `paceChoice` and `consistentWait` (`App/ReminderForm/PaceChoice.swift`) make the draft's `pace`. Ticket 08 (PR #51): Pace and Strength share `SegmentedChoiceSection`, and Every is `EveryRow`, both in `ReminderFormSheet.swift` and private to it. The Default Pace page needs those controls without the form, so expect to lift them out. Every new draft goes through one init, `ReminderForm.init(engine:now:tagIDs:)`, called from `TabScreen.swift` (+ on Now, My Day and a tag's list) and the previews. The spec says the Default pace record is injected, like `OnboardingRecord` (`App/Onboarding/OnboardingRecord.swift`, `UserDefaults`, with tests as prior art). Spec stories 36–42 and 48, and Implementation decisions: Default pace, Settings.
- Watch for: `UserDefaults` is shut before the first unlock (`AppModel.swift`, after the store loads), so a read at launch can return nothing and look like Consistent · 10 min. Read it when a draft is made, as the spec says, not cached at launch. Delete All Data (`AppModel.deleteAllData()`) leaves the onboarding record on purpose but must clear the Default pace. Ticket 10 (How It Nudges follows the Default pace) builds on this record, so give it one place to read from. The beta note's home isn't settled ("where the testers will see it"): ask Brian before writing it, for example TestFlight's What to Test or a release note in the repo.
- Developer stops: agree the `tdd` seams (the record's default and relaunch, a new draft taking it, Delete All Data clearing it); where the beta note goes; the simulator pass in `scripts/screenshots.sh`, including the walk to the Default Pace page; VoiceOver on the row and page; the offered iPhone run.
